対象は指定された設計書・実装計画・タスク JSON。完了状態との照合に必要な範囲で、現在の実装とテストも確認した。

## 1. [P2] 計画の GDI 後処理が API の解放契約に従っていない

該当: [計画](../plans/2026-10-03-desktop-vision-mcp.md)の679〜689行（ビットマップ選択・削除、DC 解放）。

`memory_dc.SelectObject(bitmap)` の戻り値を保存せず、ビットマップを選択したまま `DeleteObject` を呼んでいる。Microsoft の仕様では、DC に選択されているオブジェクトの削除は失敗するため、計画どおりの実装では後処理の成功を保証できない。また、`GetWindowDC` で取得した DC に `window_dc.DeleteDC()` を呼び、その後で `ReleaseDC` も呼んでいる。借用したウィンドウ DC と、自分で作成したメモリ DC の解放方法を分ける必要がある。[DeleteObject の仕様](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-deleteobject)、[GetWindowDC の仕様](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowdc)、[DeleteDC の仕様](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-deletedc)。

**修正案:** 元のビットマップを保存し、成功・失敗の両経路で再選択してから撮影用ビットマップを削除する。自分で作成したメモリ DC は `DeleteDC`、取得したウィンドウ DC は `ReleaseDC` で解放する。例外時もこの順序を守れるようにする。

現行実装ではビットマップの再選択は既に修正されている（`src/ai_desktop/capture.py` の211〜222行）。一方、借用 DC への `DeleteDC` は225行に残っている。計画も現在の修正を反映する必要がある。このレビューでは実機でのリソース漏れや後処理失敗の再現までは行っていない。

## 2. [P2] Chrome と VS Code の両方を確認する要件が、どちらか一方に弱められている

該当: [計画](../plans/2026-10-03-desktop-vision-mcp.md)の1055行、[設計書](../specs/2026-10-03-desktop-vision-mcp-design.md)の252行、タスク JSON の41行（Task 5 の `description`）。

設計書は **Chrome と VS Code の両方**が黒画像にならないことを求めるが、計画・タスク定義は「Chrome か VS Code」となっている。実行例も Chrome だけなので、VS Code が黒画像になっても計画の条件を満たせてしまう。

**修正案:** アプリごとに結果を確認する条件と実行手順を用意し、両方の画像内容を確認する。背面ウィンドウを撮影できることも、対象と前後関係が分かる結果で確認する。タスク定義内の受け入れ条件・メタデータも同期する。

## 3. [P2] DPI の受け入れ条件では、画像の切れ・ずれを検出できない

該当: [計画](../plans/2026-10-03-desktop-vision-mcp.md)の1056行、[設計書](../specs/2026-10-03-desktop-vision-mcp-design.md)の253行、タスク JSON の41行。

設計書は125% / 150%で画像が切れたりずれたりしないことを求める。計画では「100%以外」で、撮影メタデータのサイズと `list_monitors` のサイズが等しいことだけを判定する。両者が同じ誤った値を使っていても一致し、ウィンドウの撮影範囲や `origin` のずれも検出できない。

**修正案:** 125% / 150%の確認条件を明示し、実際の物理解像度との照合に加えて、モニター画像・ウィンドウ画像の端や目印が欠けずに写ることを確認する。座標メタデータから既知の画像上の位置が期待する画面位置に戻ることも確認する。必要な表示スケールで実行できなかった場合は、その条件を未確認として記録する。

## 4. [P2] 存在しないタイトルからの復旧が受け入れ条件にない

該当: [計画](../plans/2026-10-03-desktop-vision-mcp.md)の1058行、[設計書](../specs/2026-10-03-desktop-vision-mcp-design.md)の255行、タスク JSON の41行。

設計書は「存在しないタイトル」と「複数該当するタイトル」の両方で、Claude がエラーを読み、`list_windows` や `window_id` を使って復旧することを求める。計画・タスク定義・実行例には複数該当の場合だけが含まれる。単体テストで `CaptureError` を確認しても、Claude 側の復旧動作は確認できない。

**修正案:** 存在しないタイトルを指定する受け入れケースを追加する。該当なしのエラーを受け、`list_windows` で候補を確認し、実在する `window_id` で撮影する流れを確認する。複数該当のケースと別々に結果を記録する。
