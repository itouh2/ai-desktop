# ai-desktop: 注釈ページの「つぎやること」ボタン 設計書

- 日付: 2026-10-03
- 状態: 設計案（ユーザー確認済みの方針。実装は別の担当者が行う）
- 前提: [注釈付きスクショ表示](2026-10-03-annotated-view-design.md)、[ビューアーのクリック連動とタブの再利用](2026-10-03-viewer-click-design.md)

## 1. 目的

注釈ページに「つぎやること」ボタンを置き、押すと Claude がその時点の画面を見て、次にやることを注釈と説明文で教えるようにする。ゲームの手順案内のように「画面を進める → ボタンを押す → 次の指示が出る」を、チャットに戻らずブラウザだけで繰り返せるようにする。

## 2. スコープ

### 含める

- ページ上部の「つぎやること」ボタンと説明文の欄
- ボタンを待ち受ける MCP ツール `wait_for_next_step`
- `show_annotated` への説明文パラメーター `explanation` の追加
- ビューアーの POST `/next` と、ボタンの状態を伝える SSE イベント
- Claude 向け INSTRUCTIONS への手順の追記

### 含めない

- MCP サーバーから Claude API を直接呼ぶ方式（API キーと別料金が必要なため不採用。§3）
- Claude Code の channels（チャットへのメッセージ差し込み）を使う方式（プレビュー機能で VS Code 拡張での可否が未確認のため不採用。§3）
- ページの「案内を終わる」ボタン（チャットで Esc を押せば止まる。必要になったら追加する）
- 説明文の HTML 表示（ただの文字として表示する）

## 3. 決定事項

| 項目 | 決定 |
|---|---|
| 次にやることを考えるのは誰か | チャットの Claude。Claude がボタン待ちのツールを呼んだまま待ち、押されたら処理して再び待つ。追加料金なし。代わりにチャットは案内中ずっと「実行中」になる（ユーザー選択） |
| 撮り直しは誰がするか | MCP サーバー。押された時点で、表示中の画像と同じ対象（ウィンドウまたはモニター）を撮り直し、その画像をツールの結果として返す。Claude が別の画面を撮る取り違えを防ぐ |
| 説明文の表示先 | ページにも出す（チャットにも従来どおり書く）。ブラウザとアプリの画面だけで完結させる（ユーザー選択） |
| 説明文の扱い | プレーンテキスト。`textContent` で入れ、HTML として解釈しない |
| 待ち時間の区切り | 1 回の待ちは既定 300 秒。時間切れなら「まだ押されていない」を返し、Claude が呼び直す。Claude Code の MCP ツール待ち時間の上限で途切れないようにするため |

## 4. 構成

```
（ユーザー）「ボタンで案内して」
  └─ Claude: capture_* → show_annotated(capture_id, html, title, explanation)
        └─ Claude: wait_for_next_step(timeout_seconds=300)   ← ここで待つ
              ├─ ページのボタンが押された
              │    └─ ビューアー: 表示中の対象を撮り直す → 画像と captureId を返す
              │          └─ Claude: 画像を見て show_annotated(..., explanation) → 再び wait_for_next_step
              └─ 時間切れ → {"pressed": false} を返す → Claude が再び wait_for_next_step
```

## 5. 部品ごとの仕様

### 5.1 `wait_for_next_step(timeout_seconds: int = 300)`（新しいツール、`server.py`）

- ボタンが押されるまで待つ。待っている間、ビューアーの状態は「待ち受け中」になる。
- 押されたら、表示中の `captureId` の撮影対象（`CaptureStore.target`）を撮り直して保存し、`capture_window` / `capture_monitor` と同じ形式（JPEG ＋ メタデータ JSON、新しい `captureId` を含む）で返す。
- 時間切れなら画像なしで `{"pressed": false}` を返す。
- 撮り直しに失敗したら（ウィンドウが閉じられた、最小化された など）、既存のツールと同じくエラーとして返す。
- 表示中のページがない（`show_annotated` をまだ呼んでいない）ときは、待たずにエラーを返す。
- 同時に待てるのは 1 つだけ。2 つ目の呼び出しは、先の待ちを「取り消し」として終わらせてから待ちを引き継ぐ（中断されたターンの待ちが残っても詰まらないようにするため）。
- `timeout_seconds` は 1〜600 に丸める。

### 5.2 `show_annotated` の `explanation`（`server.py`、`viewer.py`）

- 省略可の文字列パラメーター。表示内容（SSE の `view`）に `explanation` として載せる。
- 省略時は説明欄を空にする（前の説明を残さない）。
- 長さの上限は 4,000 文字。超えたら切り詰める。

### 5.3 ビューアー（`viewer.py`）

状態を 1 つ持ち、SSE の新しいイベント `state` でページに送る。

| 状態 | 意味 | 変わるとき |
|---|---|---|
| `idle` | 誰も待っていない | 起動時、待ちが時間切れまたは取り消しで終わったとき |
| `waiting` | Claude が待ち受け中 | `wait_for_next_step` が待ち始めたとき |
| `thinking` | 押された。Claude が処理中 | `/next` を受けたとき。次の `show_annotated` か `wait_for_next_step` で抜ける |
| `error` | 撮り直しに失敗した | 撮り直しが例外で終わったとき。次の `show_annotated` か `wait_for_next_step` で抜ける |

- POST `/next`: 既存の `/click` と同じく、Host・トークン・Origin を確認する。
  - `waiting` のとき: 押されたことを記録して待ちを起こし、状態を `thinking` にして `{"ok": true}` を返す。
  - それ以外のとき: `{"error": "Claude が待ち受けていません。チャットで『ボタンで案内して』と頼んでください。"}` を返す。
- 撮り直しはクリックと同じ排他（`_operating`）の中で行う。クリック中に押されたら、クリックの終了を待ってから撮る。
- 新しくつながったタブには、接続直後に現在の状態を送る。

### 5.4 ページ（`annotate.py` の `render_shell`）

- 画像の上に横長のバーを置き、左に「つぎやること」ボタン、右に状態の文言を出す。
- 説明欄は画像の右に置く。ウィンドウ幅が狭いときは画像の下に回す。
- ボタンの表示:
  - `waiting`: 押せる。
  - `thinking`: 押せない。「考え中…」。
  - `idle`: 押せない。「チャットで『ボタンで案内して』と頼むと使えます」。
  - `error`: 押せない。「撮影できませんでした。チャットを確認してください」。
- 押したら POST `/next` を送る。エラーが返ったら、その文言を状態欄に出す（`alert` は使わない）。
- 既存の CSP（nonce 付きスクリプトのみ）はそのまま。ボタンと説明欄はシェル側に置き、Claude が書く注釈 HTML には入れない。

### 5.5 INSTRUCTIONS（`server.py`）

既存の段落に次の趣旨を追記する（1 段落を保つ）。

- ユーザーがボタンでの案内を頼んだら、`show_annotated` のあとに `wait_for_next_step` を呼ぶ。
- 画像が返ったら、それを見て次にやることを `show_annotated`（`explanation` 付き）で示し、また `wait_for_next_step` を呼ぶ。
- `{"pressed": false}` なら黙って呼び直す。
- ユーザーがチャットで別の話を始めたら繰り返しをやめる。

## 6. エラー時の動き

| 場面 | 動き |
|---|---|
| 誰も待っていないときに押した | `/next` がエラー文言を返し、ページの状態欄に出す |
| 撮り直しに失敗 | ツールがエラーを返し、ページは `error` 状態。Claude はチャットで原因を伝える |
| Claude のターンが Esc で中断された | 待ちは時間切れまで残るが、次の `wait_for_next_step` か時間切れで片づく。それまでに押された場合は撮り直した画像が誰にも読まれずに捨てられる（害はない） |
| タブが閉じられた | 既存どおり。次の `show_annotated` でブラウザを開き直す |
| MCP ツールの待ち時間上限 | 300 秒で区切るので通常は当たらない。上限の実際の値は実装時に確認し、必要なら既定値を下げる |

## 7. テスト

- 単体テスト（`tests/test_viewer.py`）
  - `idle` で `/next` を受けるとエラーになり、状態が変わらない
  - 待ち中に押すと待ちが解除され、撮り直した `captureId` が返る
  - 時間切れで `{"pressed": false}` が返り、状態が `idle` に戻る
  - 2 つ目の待ちが 1 つ目を取り消す
  - 撮り直し失敗で状態が `error` になり、ツールがエラーを返す
  - `/next` が Host・トークン・Origin の不一致を 403 で拒否する
- 単体テスト（`tests/test_annotate.py`、`tests/test_server.py`）
  - `explanation` が SSE の表示内容に載る、省略時は空、4,000 文字で切り詰められる
  - シェルの説明欄が `textContent` で入る（`<script>` を含む説明文が実行されない）
- 実機確認（`scripts/e2e_viewer.py` を拡張）
  - ページのボタン → ツールの待ち解除 → 新しい注釈の表示、までを通しで確認

## 8. 既知の制限（README に追記する）

- 案内中はチャットが「実行中」になり、そのあいだは文字で話しかけにくい。止めるときは Esc。
- ボタンで撮り直すのは、表示中の画像と同じウィンドウまたはモニターだけ。別のウィンドウを見てほしいときはチャットで頼む。
