# ai-desktop: ビューアーのクリック連動とタブの再利用 設計書

- 日付: 2026-10-03
- 状態: 設計承認済み・実装前
- 前提: [注釈付きスクショ表示](2026-10-03-annotated-view-design.md)

## 1. 目的

1. 注釈ページ上でクリック・ダブルクリックすると、実際の画面の同じ位置がクリックされるようにする（ページは更新しない。2026-10-03 のユーザーテストを受けて変更）。
2. `show_annotated` を呼ぶたびに新しいタブが開く問題を解消する。開いているタブがあれば、その中身を差し替える。

## 2. スコープ

### 含める

- PC 内だけで使う Web サーバー（ビューアー）。ページの配信、表示内容の常時送信（Server-Sent Events）、クリック要求の受け付けを担う
- タブの再利用。開いているタブがあれば内容を差し替えてブラウザを前面に出し、なければブラウザを開く
- 左クリックとダブルクリックの連動。ブラウザがクリック位置に重なるときだけ一時的に最小化し、終わったらブラウザを前面に戻す
- 高 DPI 非対応アプリのウィンドウ撮影の修正（§6.8。計画作成中に見つかった既存の不具合で、ユーザー承認済み）

### 含めない

- 右クリック、スクロール、文字入力、ドラッグ
- Claude 自身がクリックする MCP ツール（`control.py` は将来それに流用できる形にする）
- 注釈 HTML の危険なタグの拒否（ユーザー判断で今回も対応しない。§9）

### やめるもの

- 一時フォルダへの HTML 保存（`%TEMP%\ai-desktop\annotations\`、直近30件）。ページはメモリから配信するので不要になる。

## 3. 決定事項

| 項目 | 決定 |
|---|---|
| クリック後の動作 | 実際の画面をクリックするだけ。撮り直しもページの更新もしない（注釈は残る）。当初は撮り直して注釈を消す設計だったが、ユーザーテストで手順の注釈が消えて困ると分かり変更 |
| ブラウザが対象に重なる問題 | ウィンドウ撮影は対象を前面に出すだけ（ブラウザより上に来る）。画面全体の撮影はクリック位置がブラウザ内のときだけ最小化。どちらも最後にブラウザを前面に戻す |
| 伝える操作 | 左クリック、ダブルクリック |
| 方式 | MCP サーバー内に 127.0.0.1 だけで待ち受ける Web サーバーを持つ（標準ライブラリのみ） |
| 危険なタグの拒否 | 今回もしない（既知の制限のまま） |
| 高 DPI 非対応アプリの撮影 | 今回直す（クリック位置の正確さに直結するため） |

## 4. 試作で確認したこと（2026-10-03、この PC）

| 操作 | 結果 |
|---|---|
| 裏のプロセスからの `SetForegroundWindow` | 戻り値は成功だが、前面にならない（Windows の前面化ロック） |
| 同上、Alt キーを一瞬押してから | 毎回成功 |
| ブラウザの最小化 | 成功 |
| 最小化したブラウザを元に戻して前面に | Alt キーなしで成功 |
| `SetCursorPos`＋`SendInput` によるクリック、マウス位置の復元 | 成功 |
| 前面化の直後にクリック | まれに取りこぼす。前面化の成功後に 0.15 秒待つと、3 回続けて取りこぼしなし |
| クリック中に利用者がマウスを動かす | 座標なしのボタン操作では 5 回中 1 回しか届かない。ボタン操作に絶対座標（仮想デスクトップ全体を 0〜65535 に正規化）を持たせると 5 回中 5 回届く |
| 参考実装での通しテスト（MCP サーバー経由） | タブの再利用、ページ経由のクリック・ダブルクリックの到達を確認 |

## 5. 構成

```
show_annotated(capture_id, html, title)
  └─ Viewer.publish → 表示内容を更新し、SSE で配信
        ├─ 開いているタブが 1.5 秒以内に受け取りを返した → ブラウザを前面に → 「既存のタブを更新しました」
        └─ 返事がない → 既定のブラウザで URL を開く → 「ブラウザで開きました: <URL>」

ページでクリック
  └─ POST /click {captureId, x, y, double}
        └─ Viewer.perform_click
              （ウィンドウ撮影なら）対象を前面に → 今の位置から画面座標を計算 → （画面全体の撮影でブラウザと重なるなら）ブラウザを最小化して 0.15 秒待つ
              → クリック → マウス位置を戻し、ブラウザを前面に戻す（ページはそのまま）
```

## 6. 詳細

### 6.1 撮影の記録（CaptureStore）

- `Target(kind: "monitor" | "window", id: int)` を、撮影ごとに一緒に保存する。
- `target(capture_id) -> Target`。見つからない場合と、対象の記録がない場合は `CaptureError`。

### 6.2 座標

- 画像上の座標 (x, y) は、ページの `#stage` 上のクリック位置を、表示倍率で割って求める。
- 画面座標は `image_to_screen(meta, x, y, origin)` で求める。
  - モニター撮影では、撮影時の origin をそのまま使う。
  - ウィンドウ撮影では、対象を前面に出したあとの**今の**ウィンドウの左上を origin に使う。撮影後にウィンドウが動いていてもずれない。
- 画像の範囲外の座標はエラーにする。

### 6.3 Web サーバー

- `ThreadingHTTPServer(("127.0.0.1", 0))`。最初の `show_annotated` で起動し、MCP サーバーのプロセスが終わるまで動かす。
- 合言葉：起動ごとに `secrets.token_urlsafe(24)`。URL は `http://127.0.0.1:<port>/?t=<合言葉>`。

| 窓口 | 認証 | 内容 |
|---|---|---|
| `GET /` | クエリ `t` と Host | ページの枠組み。CSP は HTTP ヘッダーで送る |
| `GET /events` | クエリ `t` と Host | SSE。接続時に現在の表示内容を送り、以後は更新のたびに `event: view` を送る。15 秒ごとに `: ping`（閉じたタブの検出） |
| `GET /image/<captureId>` | クエリ `t` と Host | 背景の JPEG |
| `POST /ack` | ヘッダー `X-AI-Desktop-Token`、`Origin`、Host | `{version}`：ページが表示内容を受け取ったことを知らせる |
| `POST /click` | 同上 | `{captureId, x, y, double}` → `{ok, captureId}` または `{error}` |

- **Host の確認**：`Host` が `127.0.0.1:<port>` と一致すること（DNS リバインディング対策）。
- **Origin の確認**：POST の `Origin` が `http://127.0.0.1:<port>` と一致すること。独自ヘッダーが必要なので、他サイトのページからはプリフライトで止まる（CORS には応答しない）。
- **共通ヘッダー**：`Cache-Control: no-store`、`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff`
- **CSP**：`default-src 'none'; img-src 'self'; style-src 'unsafe-inline'; script-src 'nonce-<毎回ランダム>'; connect-src 'self'`
- 本文は最大 1024 バイト。ログは `logging` 経由（標準出力には書かない）。

### 6.4 タブの再利用

- `publish` は表示内容を更新して全タブに送り、つながっているタブがあれば、`/ack` が返るのを最大 1.5 秒待つ。
- 返ってきたら、タイトルが `ai-desktop | ` で始まるウィンドウを探して前面に出す（できなければ何もしない）。
- 返ってこなければ（タブを閉じた直後など）、ブラウザで URL を開く。新しいタブは接続時に現在の表示内容を受け取る。

### 6.5 ページ

- タイトルは `ai-desktop | <title>`。ブラウザのウィンドウを探す手がかりにする。
- `#stage` 全体でクリックを受ける。1 回目のクリックは 300ms 待ち、2 回目が来たらダブルクリックとして送る。
- 操作中は右上に「クリック中…」を表示し、追加のクリックは無視する。エラーは赤い表示で出す。
- Claude の HTML は `innerHTML` で差し込む。中の `<script>` は実行されず、イベント属性も CSP で止まる。
- SSE の接続が切れたら「サーバーとの接続が切れました」と表示する。

### 6.6 クリック操作（Viewer.perform_click）

1. 操作中なら「ほかの操作を実行中です」でエラー（同時に1つだけ）。
2. captureId から背景・メタデータ・Target を取得し、画像の範囲内か確認する。
3. ブラウザ（タイトルが `ai-desktop | `）のウィンドウを探す。Target がそのウィンドウと同じならエラー（同じウィンドウの別タブは操作できない）。
4. マウスの位置を記録する。
5. ウィンドウ撮影なら、対象を前面に出してから今の左上を取得する（前面に出せなければエラー）。
6. 画面座標を求める。画面全体の撮影でその点がブラウザのウィンドウ内なら、ブラウザを最小化して 0.15 秒待つ。
7. クリックする（ダブルクリックは 50ms 空けて 2 回）。
8. （成功・失敗にかかわらず）マウス位置を戻し、ブラウザを元に戻して前面に出す。ページは更新しない。

### 6.7 show_annotated の戻り値とエラー

- 戻り値：「既存のタブを更新しました。」または「ブラウザで開きました: <URL>」
- Web サーバーを起動できない：「表示用のローカルサーバーを起動できませんでした: …」
- ブラウザを開けない：「ブラウザで開けませんでした: <URL>（…）」
- 既存の検証（html が空、長すぎる、captureId が見つからない）はそのまま。

### 6.8 高 DPI 非対応アプリの撮影

- 高 DPI 非対応のウィンドウは、Windows が画面上で引き伸ばして表示している。PrintWindow はそれを引き伸ばす前の大きさで描くため、画像の左上の一部（150% なら 2/3）にしか中身が写らず、残りが黒くなる。
- `GetDpiForWindow`（そのウィンドウの DPI）と、`GetDpiForMonitor`（表示しているモニターの実効 DPI）を比べる。ウィンドウ側が小さければ、写った部分（幅・高さ × 比率）を切り出し、元のサイズに拡大する（`restore_dpi_scaling`）。
- 撮影画像の座標系は物理ピクセルのままなので、メタデータとクリック位置の換算はそのまま正しい。

## 9. 既知の制限

- 注釈 HTML の `<meta http-equiv="refresh">` やリンクなどによるページ移動は防げない（前回からの継続、ユーザー判断）。
- ビューアーのタブがあるブラウザのウィンドウは、画面全体の撮影でクリック位置に重なるときに最小化される。また、そのウィンドウ自身を対象にした操作はできない（エラーにする）ので、同じウィンドウの別タブを操作したいときは別ウィンドウに分ける。
- 前面化に Alt キーの回避策を使うので、まれにアプリのメニューバーが一瞬反応することがある。
- 管理者権限で動くアプリは、通常権限のサーバーからはクリックできない（Windows の UIPI）。
- MCP サーバー（Claude Code のセッション）が終わると、開いているタブは「接続が切れました」になる。次の `show_annotated` で新しいタブが開く。
