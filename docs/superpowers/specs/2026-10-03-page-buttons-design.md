# ai-desktop: 注釈ページのボタンで AI が反応する仕組み 設計書

- 日付: 2026-10-03
- 状態: 設計承認済み・実装前
- 前提: [注釈付きスクショ表示](2026-10-03-annotated-view-design.md)、[ビューアーのクリック連動とタブの再利用](2026-10-03-viewer-click-design.md)
- 経緯: 当初は固定の「つぎやること」ボタンの設計案だった。ユーザーの依頼で「ボタンを押すと AI が反応できる汎用の仕組み」に変更した（2026-10-03）。

## 1. 目的

注釈ページに Claude が決めたボタン（例:「できた」「どこか分からない」「やめる」）を並べ、ユーザーが押すと、押されたボタン名と撮り直した画面が Claude に届き、Claude がそれに応じて反応できるようにする。手順の案内、選択肢を選んでもらう、確認をもらう、といったやりとりを、チャットに戻らずブラウザとアプリの画面だけで繰り返せるようにする。

## 2. スコープ

### 含める

- `show_annotated` の新しい引数 `buttons`（ボタン名の配列）と `explanation`（説明文）
- ページ上部のボタン欄と状態の表示、画像の横の説明欄
- ボタンが押されるまで待つ MCP ツール `wait_for_button`
- ビューアーの POST `/press` と、状態を伝える SSE イベント `state`
- 撮り直し関数 `_recapture(target)` の復活（クリック連動の変更で一度削除したもの）
- Claude 向け INSTRUCTIONS への使い方の追記

### 含めない

- 自由入力欄（ユーザーが選んだ方式は「ボタンだけ、Claude が毎回決める」）
- MCP サーバーから Claude API を直接呼ぶ方式、Claude Code の channels を使う方式（追加料金や未確認の機能を避けるため）
- 説明文やボタン名の HTML 表示（ただの文字として表示する）

## 3. 決定事項

| 項目 | 決定 |
|---|---|
| ボタンを決めるのは誰か | Claude が `show_annotated` のたびに `buttons` で決める（ユーザー選択）。最大 6 個、1 つ 30 文字まで。指定しなければボタン欄は出ない |
| 反応を考えるのは誰か | チャットの Claude。`wait_for_button` を呼んだまま待ち、押されたら処理して再び待つ。追加料金なし。代わりに、やりとりの間チャットは「実行中」になる |
| 撮り直しは誰がするか | MCP サーバー。押された時点で、表示中の画像と同じ対象（ウィンドウまたはモニター）を撮り直して返す。Claude が別の画面を撮る取り違えを防ぐ |
| 説明文の表示先 | ページにも出す（チャットにも従来どおり書く） |
| 説明文・ボタン名の扱い | プレーンテキスト。`textContent` で入れ、HTML として解釈しない |
| 待ち時間の区切り | 1 回の待ちは既定 90 秒（上限 110 秒）。時間切れなら `{"pressed": null}` を返し、Claude が呼び直す。Claude Code は会話中に 2 分を超えた MCP ツール呼び出しを自動でバックグラウンドに回す（`CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`、既定 120000）ため、その前に必ず戻す。ツールの待ち時間の上限（`MCP_TOOL_TIMEOUT`、既定で約 28 時間）には当たらない |

## 4. 構成

```
Claude: capture_* → show_annotated(capture_id, html, title, explanation, buttons=["できた", "分からない"])
  └─ Claude: wait_for_button(timeout_seconds=90)   ← ここで待つ
        ├─ ページでボタンが押された（POST /press {"button": "分からない"}）
        │    └─ ビューアー: 状態を thinking に → ツールの待ちを起こす
        │          └─ サーバー: 表示中の対象を撮り直す → {"pressed": "分からない", ...メタデータ} ＋ 画像を返す
        │                └─ Claude: 画像を見て show_annotated(...) → 再び wait_for_button
        └─ 時間切れ → {"pressed": null} → Claude が再び wait_for_button
```

## 5. 部品ごとの仕様

### 5.1 `show_annotated` の新しい引数（`server.py`、`viewer.py`）

- `explanation: str | None`：説明文。表示内容（SSE の `view`）に `explanation` として載せる。省略時は空（前の説明を残さない）。4,000 文字を超えたら切り詰める。
- `buttons: list[str] | None`：ボタン名。表示内容に `buttons` として載せる。省略時は空（ボタン欄を出さない）。前後の空白を除き、空のものは捨てる。7 個以上、または 30 文字を超える名前、同じ名前の重複はツールエラーにする。

### 5.2 `wait_for_button(timeout_seconds: int = 90)`（新しいツール、`server.py`）

- `timeout_seconds` は 1〜110 に丸める。
- 表示中のページがない、または表示中のページにボタンがないときは、待たずにツールエラーを返す。
- ボタンが押されるまで待つ。待っている間、ビューアーの状態は `waiting`。
- 押されたら、表示中の `captureId` の撮影対象（`CaptureStore.target`）を `_recapture` で撮り直して保存し、`capture_window` / `capture_monitor` と同じ形式（JPEG ＋ メタデータ JSON）で返す。メタデータの先頭に `"pressed": "<ボタン名>"` を加える。
- 時間切れなら画像なしで `{"pressed": null}` を返す。
- 撮り直しに失敗したら（ウィンドウが閉じられた、最小化された など）、ツールエラーを返し、ビューアーの状態を `error` にする。
- 同時に待てるのは 1 つだけ。新しい待ちは古い待ちを取り消し（古い方は `{"pressed": null}` で終わる）、待ちを引き継ぐ。中断されたターンの待ちが残っても詰まらないようにするため。
- Esc で中断したときにサーバーへ取り消し通知（`notifications/cancelled`）が届くかは、ドキュメントに記載がないため実装時に実機で確かめる。届かなくても、次の待ちによる取り消しと時間切れで片づく。

### 5.3 ビューアー（`viewer.py`）

状態を 1 つ持ち、SSE の新しいイベント `state` でページに送る。新しくつながったタブには、接続直後に現在の状態を送る。

| 状態 | 意味 | 変わるとき |
|---|---|---|
| `idle` | 誰も待っていない | 起動時、待ちが時間切れで終わったとき |
| `waiting` | Claude が待ち受け中 | `wait_for_button` が待ち始めたとき |
| `thinking` | 押された。Claude が処理中 | `/press` を受けたとき。次の `show_annotated` か `wait_for_button` で抜ける |
| `error` | 撮り直しに失敗した | 撮り直しが例外で終わったとき。次の `show_annotated` か `wait_for_button` で抜ける |

- POST `/press {"button": "<名前>"}`：既存の `/click` と同じく、Host・トークン・Origin を確認する。
  - `waiting` で、名前が表示中のボタンにあるとき：押されたボタンを記録して待ちを起こし、状態を `thinking` にして `{"ok": true}` を返す。
  - 待ち受けていないとき：`{"error": "Claude が待ち受けていません。チャットで、ボタンで進めたいと頼んでください。"}`。
  - 表示中にない名前：`{"error": "そのボタンは今は使えません。"}`。
- 撮り直しは、クリックと同じ排他（`_operating`）の中で行う。クリック中に押されたら、クリックの終了を待ってから撮る。

### 5.4 ページ（`annotate.py` の `render_shell`）

- 画像の上に横長のバーを置き、左に Claude のボタン、右に状態の文言を出す。ボタンがないときはバーごと隠す。
- 説明欄は画像の右に置く（幅が狭いときは下に回る）。説明が空なら隠し、画像を幅いっぱいに出す。
- ボタン名と説明文は `textContent` で入れる。
- 状態ごとの表示:
  - `waiting`：ボタンを押せる。状態欄は空。
  - `thinking`：ボタンは押せない。「考え中…」。
  - `idle`：ボタンは押せない。「Claude が待ち受けると押せます」。
  - `error`：ボタンは押せない。「撮影できませんでした。チャットを確認してください」。
- 押したら POST `/press` を送る。エラーが返ったら、その文言を状態欄に出す（`alert` は使わない）。
- 既存の CSP（nonce 付きスクリプトのみ）はそのまま。ボタンと説明欄はシェル側に置き、Claude が書く注釈 HTML には入れない。

### 5.5 INSTRUCTIONS（`server.py`）

既存の段落に次の趣旨を追記する（1 段落を保つ）。

- ページでのやりとり（手順の案内、選択肢を選んでもらう、確認をもらうなど）が役に立つときは、`show_annotated` に `buttons`（と `explanation`）を付けて表示し、`wait_for_button` を呼ぶ。
- 押されたボタン名と撮り直した画面が返るので、それに応じて反応し、続けるならまた `buttons` 付きで表示して `wait_for_button` を呼ぶ。
- `{"pressed": null}` なら黙って呼び直す。ユーザーがチャットで別の話を始めたら繰り返しをやめる。

## 6. エラー時の動き

| 場面 | 動き |
|---|---|
| 誰も待っていないときに押した | `/press` がエラー文言を返し、ページの状態欄に出す |
| ボタンのないページで `wait_for_button` | 待たずにツールエラー |
| 撮り直しに失敗 | ツールがエラーを返し、ページは `error` 状態。Claude はチャットで原因を伝える |
| Claude のターンが Esc で中断された | 待ちは時間切れまで残るが、次の `wait_for_button` か時間切れで片づく。その間に押された場合、撮り直した画像は誰にも読まれずに捨てられる（害はない） |
| タブが閉じられた | 既存どおり。次の `show_annotated` でブラウザを開き直す |
| MCP ツールの待ち時間・バックグラウンド化 | 1 回 90 秒（上限 110 秒）で区切るので当たらない |

## 7. テスト

- `tests/test_viewer.py`
  - 待ち受けていないときの `/press` はエラーで、状態は変わらない
  - 待ち中に表示中のボタンを押すと待ちが解除され、押されたボタン名が返る。表示中にない名前は拒否される
  - 時間切れで `None` が返り、状態が `idle` に戻る
  - 新しい待ちが古い待ちを取り消す
  - 撮り直し失敗で状態が `error` になる。次の表示で `idle` に戻る
  - `/press` が Host・トークン・Origin の不一致を 403 で拒否する
  - SSE が接続直後に `state` を送る。表示内容に `explanation` と `buttons` が載る
- `tests/test_server.py`
  - `buttons` と `explanation` が表示内容に渡る。7 個以上・30 文字超・重複はエラー。4,000 文字で切り詰める
  - `wait_for_button`：押されたら画像とメタデータ（`pressed` 付き）、時間切れなら `{"pressed": null}`、待ち時間は 1〜110 に丸める、ボタンのないページではエラー
  - `_recapture` が同じ対象を撮り直す
- `tests/test_annotate.py`
  - シェルにボタン欄・状態欄・説明欄があり、ボタン名と説明を `textContent` で入れる
- 実機確認（`scripts/e2e_viewer.py` を拡張）
  - MCP サーバー経由で、ボタン付き表示 → `wait_for_button` → ページの `/press` → 押されたボタン名と撮り直した画面が返る、までを通しで確認する
  - Esc での中断時に `notifications/cancelled` が届くかを確かめ、結果をこの設計書に追記する

## 8. 既知の制限（README に追記する）

- ボタンでのやりとりの間、チャットは「実行中」になる。止めるときは Esc。
- ボタンで撮り直すのは、表示中の画像と同じウィンドウまたはモニターだけ。別のウィンドウを見てほしいときはチャットで頼む。
