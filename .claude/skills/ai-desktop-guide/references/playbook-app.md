# アプリ操作の案内（操作・設定）

Windows のアプリの操作や設定を、画面を見ながら案内するときの手引き。
ツールの基本（撮影、注釈、ページでのやりとり、カーソル）は、このスキルの `SKILL.md` にある。

## 1. 始める前に

1. ユーザーが最終的にしたいことを確かめる（例: 「この表を PDF で送りたい」「通知を止めたい」）。目的が分かれば、近道や安全なやり方を選べる。
2. `notes/README.md`（索引）にそのアプリがあれば、フォルダの `README.md` を読む（メニューや設定の場所、バージョンの違い）。
3. 撮影は基本 `capture_monitor`。ダイアログ・メニュー・ツールチップは別ウィンドウで出るので、`capture_window` には写らない。
4. モニターが複数あれば、`list_monitors` で、アプリのあるモニターを確かめる。

## 2. ページの作り方（1 ページ 1 手順）

- 1 ページに 1 手順。押す場所を枠（`.box`）と番号（`.badge`）で示す。
- 説明文には、画面に見えているとおりの表記で、メニューの道筋を書く（例: 「ファイル → エクスポート → PDF/XPS ドキュメントの作成」）。
- ボタンは、結果を返す名前にする（「できた」「見つからない」など）。
- 入力欄も出すと、想定外のこと（「別の画面が出た」など）が届く。
- 「まとめて」と頼まれたら、その画面でやることを ①②③ の順で 1 ページにまとめる。

## 3. 「できた」のあと

1. 一緒に返る撮り直し画像で、結果を確かめる（ダイアログが開いた、設定が変わった など）。
2. 期待どおりなら、次の手順を出す。
3. 違っていれば、同じ手順を詳しく出し直す（枠を大きく、説明を具体的に）。

「見つからない」と返ったら、撮り直し画像で、その場所が画面に出ているかを確かめる。隠れていれば（スクロールの外、閉じたメニュー、狭いウィンドウ など）、出し方から案内する。

## 4. 取り消せない操作の前

対象: 削除、送信、購入、上書き、インストール、セキュリティに関わる設定。

1. 何が起きるかを説明文に書く（消えるもの、送り先、かかるお金、変わる設定）。
2. ページのボタンで確認をとる（例: `["進める", "やめておく"]`）。
3. 「進める」が押されてから、押す場所を示して案内する。

確認をとるページでは、まだ押す場所を示さない。ページの画像のクリックは、実際の画面に届くため。

## 5. 画面が想定と違うとき

- バージョンや言語の違いで、メニューの名前や場所が違うことがある。
- 違うと分かったら、そうユーザーに伝える。
- ウェブで調べる（Firecrawl の `firecrawl_search` / `firecrawl_scrape`、使えなければ WebSearch）。出典の URL を添える。
- アプリのバージョンは、多くの場合「ヘルプ → バージョン情報」で確かめられる。

## 6. notes に残す

- メニューや設定の場所（画面に見えるとおりの表記で）
- バージョンの違い（どのバージョンで、どこが違ったか）
- つまずいた点（見つけにくい場所、紛らわしい名前）

書き方（置き分け、確かさの印）は、同じフォルダの `notes-format.md` に従う。
