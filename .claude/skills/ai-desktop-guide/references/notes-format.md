# 知見（notes）の書き方

アプリやゲームごとの知見は、リポジトリ直下の `notes/` に置く。
次の回の Claude が読んで、同じことを調べ直さずに済むように書く。

## 1. フォルダの形

```text
notes/
  README.md                  索引（アプリ名・フォルダ・見分け方）
  <アプリ>/
    README.md                アプリ全体: 概要、画面の見方（領域と座標の目安）、ルールと注意、用語、未確認
    <区分>/ や <区分>.md     キャラ、敵、イベント、持ち物、作業の流れ、設定 など
    sessions/<日付>-<内容>.md  その回の記録: 結果、判断、失敗の原因
```

- フォルダ名は英小文字とハイフン（例: `slay-the-spire-2`、`excel`）。
- 区分は、1 ファイルで足りれば `<区分>.md`。項目ごとに分けたいときは `<区分>/` のフォルダにする（例: `characters/regent.md`）。
- `sessions/` のファイル名は `<日付>-<内容>.md`。日付は `YYYY-MM-DD`（例: `2026-10-05-regent.md`）。
- `sessions/` のファイルには、結果、大事な判断とその理由、失敗の原因、次に生かすことを書く。
- 名前（メニュー、ボタン、用語）は、画面に見えるとおりの表記で書く。

## 2. 索引 `notes/README.md`

1 アプリ 1 行の表にする。

| アプリ | フォルダ | 見分け方 |
|---|---|---|
| Slay the Spire 2 | `slay-the-spire-2/` | ウィンドウタイトル「Slay the Spire 2」 |

- 見分け方は、撮影の前に確かめられるもの（ウィンドウタイトル、実行ファイル名 など）。
- 新しいアプリを扱ったら、ここに 1 行足す。

## 3. 置き分け

| 内容 | 置き場所 |
|---|---|
| アプリ共通の事実 | アプリの `README.md` か区分ファイル |
| 区分に固有のこと | 区分ファイル |
| その回の出来事（結果、判断、失敗の原因） | `sessions/<日付>-<内容>.md` |
| アプリを問わない使い方のコツ | notes に書かない。スキルの手引き（`SKILL.md`、`references/` の手引き）の改善として、ユーザーに提案する |

- 同じことを 2 か所に書かない。1 か所にまとめ、ほかからはファイル名で指す。
- Claude が間違えたこと（思い込み）は、正しい内容と一緒に「注意」として書く。アプリ全体のことは README の「ルールと注意」、区分のことは区分ファイルの「注意」の節。

## 4. 確かさの印

事実ごとに、文の終わりに（ ）で印を付ける。

| 印 | 意味 |
|---|---|
| 確実 | 画面の説明文で読んだ |
| 観察 | 数字で確かめた（画面の数字の変わり方を見た） |
| ユーザーの教え | ユーザーに教わった |
| 推測 | まだ確かめていない |

例:

```text
- 予告の数字は、背後からの攻撃の上乗せ込み。向きを変えたら 21 → 14 に下がった（観察）
- 紫の札の予告は、状態異常を入れてくるもの（推測）
- 「上書き保存」のツールチップに「Ctrl+S」と出る（確実）
```

- 理由を添えるときは「（推測: …）」のように書く。
- 調べたことには、出典の URL を添える（例: 「（出典: <URL>）」）。
- 表や節の全体が同じ確かさなら、表や節の頭に 1 回書けばよい（例: 「この表は、カーソルで読んだ画面の説明文（確実）」）。
- 推測には必ず印を付ける。
- 確かめたら、印を替える（推測 → 観察 など）。間違いと分かったら直す。

## 5. 書く時

- カーソルで読んだ説明文: その場で（読んだ時点で）書く。
- ユーザーの指摘（Claude の誤りの訂正など）: その場で書く。
- 教わったこと、結果と教訓: セッションの終わり（または頼まれたとき）に書く。

## 6. アプリの README のひな形

新しいアプリのフォルダを作るときは、次の形で `README.md` を書く。

```markdown
# <アプリ名>

## 概要
何のアプリ（ゲーム）か、確かめたバージョンと言語、ウィンドウタイトル、このフォルダのほかのファイル。

## 画面の見方
どこに何が出るか（領域と座標の目安）。座標は撮影画像の大きさ（例: 1568×917）と一緒に書く。

## ルールと注意
アプリ全体に通じる決まりと、間違えやすいこと（確かさの印を付ける）。

## 用語
画面に出る言葉と、その意味。

## 未確認
まだ確かめていないこと、次に調べること。
```
